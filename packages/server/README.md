# @novaland/server

The authoritative world server (ticket #17, ADR 0004 and 0005): one Colyseus room that owns the only live sim, steps it, and tells every player what the world looks like.

```bash
PORT=5117 pnpm --filter @novaland/server dev   # default port 2567 when PORT is unset; a busy PORT fails the boot
pnpm sim:headless                               # the sim alone, five simulated seconds, prints a state hash
```

Only the shell environment is read (`@colyseus/core` and `@colyseus/ws-transport` are imported directly; the `colyseus` meta-package would also load `@colyseus/tools`, which reads `.env` files). `express` and `@colyseus/schema` are in the dependencies because they are required peers of the transport and of core; nothing here imports them. The boot prints one JSON line with the port, the room id, the seed of this boot (random, so a session can be replayed) and the rates; `SIGINT`/`SIGTERM` print the tick, the seats taken and the dropped-message counters, then stop. Colyseus answers `GET /__healthcheck` with `OK`.

## The room

- One `WorldRoom` is created at boot (`startWorldServer`) with room id `world`; clients join it with `joinById('world')`. The matchmaker only exposes `joinById`: `create`, `join`, `joinOrCreate` and `reconnect` are refused (code 520, "invalid method"), so a client can neither spawn a second world nor join one by name, and a dropped connection simply joins again as a new session.
- `maxClients = 5`. A sixth `joinById` is refused by the matchmaker with a `MatchMakeError` whose code is 522 (`ErrorCode.MATCHMAKE_INVALID_ROOM_ID`) and whose message says the room is locked; the room never locks for any other reason, so a client shows that as "world is full" (the same code with "not found" means the room does not exist yet). `JOIN_REFUSAL.worldFull` guards the seat allocation behind the matchmaker. Seat reservations expire after 3 s (`SEAT_RESERVATION_SECONDS`), so bare matchmaking requests cannot hold the world locked.
- The room steps the sim with the same whole-tick arithmetic as the client (`takeWholeTicks`): real time earns ticks of `FIXED_DT`, catch-up is capped at `MAX_CATCH_UP_SECONDS`, and nothing else calls `step`. A throw from the sim or the room is logged with the seed and the tick, then rethrown: the process dies loudly and whatever supervises it restarts a fresh world.
- Seats are slots 0-4, lowest free first. A join queues `player/join`; the welcome (`world/welcome`) carries the full state taken after the tick that processed it, so the client finds its own entity in it. A leave, consented or dropped, frees the seat and queues `player/leave`. A session that has not acknowledged its join `JOIN_ACK_TIMEOUT_MS` after its welcome is closed (Colyseus would otherwise buffer every update for it without bound); a client must register its update handlers before awaiting the welcome, see ADR 0005.
- Inbound messages pass the edge gate in `src/world/inbound.ts`: only `player/move` and `world/resync` are handled; every other type is dropped and counted, and a session that keeps sending unknown types past its budget is closed. Each session has a token budget (`INBOUND_BURST`, then `INBOUND_MESSAGES_PER_SECOND`; over it, dropped), a decoded payload longer than `MAX_INBOUND_BYTES` is dropped, and a move must be exactly `{ x, y }` with finite numbers, so a payload that carries a `slot` is dropped. The command that reaches the sim carries the session's slot, never anything from the payload. Frames over `MAX_FRAME_BYTES` are refused by the transport, which closes that connection (code 1009, with one `Max payload size exceeded` stack trace in the log per attempt); a flood past `DISCONNECT_MESSAGES_PER_SECOND` is disconnected by Colyseus. HTTP request bodies are read here first, capped at `MAX_REQUEST_BODY_BYTES`: a bigger one is answered 413 and its connection closed, and Colyseus never sees it. The cap wraps Colyseus's one HTTP `request` listener and the server refuses to boot if it finds a different number, so add HTTP routes through Colyseus's router, never with `httpServer.on('request')`.
- Outbound: every `TICKS_PER_SEND` ticks each welcomed session gets a `world/delta` diffed from the last state sent to it (sessions at the same tick share one diff), or a `world/state` if it asked for one with `world/resync` (many requests collapse into one state, and resyncs have their own small budget: `RESYNC_BURST`, then `RESYNCS_PER_SECOND`).

Tuning lives in `src/world/tuning.ts`; game rules do not live here at all.

## Tests

`pnpm --filter @novaland/server test` runs the unit tests of the gate, the seats, the tick helper and the body cap's one-listener check, plus `worldRoom.test.ts`: a real server on a free port and real `@colyseus/sdk` clients that build replicas from what they receive, covering five joins on distinct avatars and tiles, movement seen by everyone, the refused sixth, a leaver's freed seat and vanished avatar, junk dropped while the world runs, a move flood, an unknown-type flood, a refused frame, a resync and a resync flood, a connection that never acknowledges its join, an oversized HTTP body, and the room driven directly through a join that leaves mid-tick and a dispose during a join.
