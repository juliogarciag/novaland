# @novaland/server

The authoritative world server (ticket #17, ADR 0004 and 0005): one Colyseus room that owns the only live sim, steps it, and tells every player what the world looks like.

```bash
PORT=5117 pnpm --filter @novaland/server dev   # from source; default port 2567 when PORT is unset; a busy PORT fails the boot
pnpm build && PORT=5117 pnpm start             # the built bundle (dist/index.mjs), serving the built client too
pnpm sim:headless                               # the sim alone, five simulated seconds, prints a state hash
```

Only the shell environment is read (`@colyseus/core` and `@colyseus/ws-transport` are imported directly; the `colyseus` meta-package would also load `@colyseus/tools`, which reads `.env` files). `@colyseus/schema` is in the dependencies because it is a required peer of core; nothing here imports it. The boot prints one JSON line with the port, the room id, the seed of this boot (random, so a session can be replayed), the rates, the client directory served and the allowed origins; `SIGINT`/`SIGTERM` print the tick, the seats taken and the dropped-message counters, then stop.

## One process, one port (ticket #19, ADR 0008)

The same process is the whole deployment (see "Running it yourself" in the root README and the `Dockerfile`). The server is two halves that never import each other, each behind one entry file, and lint enforces it:

- `src/front/` is everything between the port and the room: the HTTP server, the routes, the origin policy and the request guard. It imports Express and never Colyseus or the world.
- `src/world/` is the room. It never imports the front or an HTTP library. It declares what it needs from a front in `WorldFront` and hands each piece to the Colyseus hook made for it.
- `src/startServer.ts` is the only file that joins them: it builds the front, then starts the world on it. `src/index.ts` reads the environment, with a helper from each entry file.

What the front is made of:

- `createFront.ts` creates the HTTP server and bundles the pieces below, each shaped for a Colyseus hook: the server goes to the transport, `mountRoutes` is the `express` option, `matchmakingHeaders` replaces the matchmaker's `getCorsHeaders`. A connection on which no byte moves is closed after a minute (`tuning.ts`); a seated player is never cut.
- `mountFrontRoutes.ts` mounts the routes that are not Colyseus's own on the Express app Colyseus hands out. Libraries do the work: `helmet` writes the security headers (a Content-Security-Policy that names what the bundle needs, `nosniff`, `X-Frame-Options: DENY`; no HSTS, which is the host's call), `express.static` serves the built client in `CLIENT_DIR` (default `packages/client/dist`): conditional and range requests, `HEAD`, no dotfiles, no path out of the directory, no directory redirects, files under `assets/` cached for a year because their names are content hashes. `compression` compresses whole responses. An error (a range that cannot be satisfied, say) is answered with its status and logs no stack trace. `GET /health` answers `200 {"ok":true,"roomId","seats","seatsTaken","tick"}`, or `503 {"ok":false}` until the room exists, never cached.
- `origins.ts` is the origin policy. Allowed: no `Origin` (not a browser), the origins in `ALLOWED_ORIGINS`, and any loopback page when `NODE_ENV` is not `production` (the dev flow: Vite on one port, the room on another). An `Origin` header counts only in the exact spelling browsers send. The policy never reads `Host`: a domain pointed at this server's address names itself in both headers, and a proxy may rewrite `Host`. `ALLOWED_ORIGINS=*` allows everything. A malformed entry stops the boot, and so does production with nothing listed.
- `guardRequests.ts` is the one place listeners are taken off the HTTP server. Colyseus answers its own routes before the Express app with no hook in front of them, and its `beforeUpgrade` hook cannot be used (with it set, the transport throws on an upgrade target that is no URL before the hook runs, and never closes a socket the hook refuses), so the guard wraps the single `request` listener and the single `upgrade` listener Colyseus installs, right after it binds its routes, and refuses to install over any other number. It answers `400` to a request or upgrade Colyseus cannot survive (it throws outside any handler on a `Host`, an `X-Forwarded-Proto` or a request target that does not make a URL, which ends the process), `403` to an upgrade or a state-changing request from an origin the policy does not allow (the upgrade is the way into the room, matchmaking reserves a seat), and `413` to a body over `MAX_REQUEST_BODY_BYTES` (`tuning.ts`), which it reads first because Colyseus reads bodies without a limit. It closes a connection that sends a request before an earlier answer is out: Node would start them all at once, and a client that then hangs up leaves every file opened for them open. A refused request or upgrade has its connection destroyed, so a client that stays on holds nothing. Add HTTP routes in `mountFrontRoutes.ts`, never with `httpServer.on('request')`.

A busy `PORT` fails the boot, and a boot that fails after the port opened closes it.

`pnpm --filter @novaland/server build` bundles `src/index.ts` with Vite into `dist/index.mjs` plus the Rapier chunk it loads on demand; the sim and its dependencies are bundled in, Colyseus, Express and their peers stay in `node_modules`. `start` runs that file with plain `node`.

## The room

- One `WorldRoom` is created at boot (`startWorldServer`) with room id `world`; clients join it with `joinById('world')`. The matchmaker only exposes `joinById`: `create`, `join`, `joinOrCreate` and `reconnect` are refused (code 520, "invalid method"), so a client can neither spawn a second world nor join one by name, and a dropped connection simply joins again as a new session.
- `maxClients = 5`. A sixth `joinById` is refused by the matchmaker with a `MatchMakeError` whose code is 522 (`ErrorCode.MATCHMAKE_INVALID_ROOM_ID`) and whose message says the room is locked; the room never locks for any other reason, so a client shows that as "world is full" (the same code with "not found" means the room does not exist yet). `JOIN_REFUSAL.worldFull` guards the seat allocation behind the matchmaker. Seat reservations expire after 3 s (`SEAT_RESERVATION_SECONDS`), so bare matchmaking requests cannot hold the world locked.
- The room steps the sim with the same whole-tick arithmetic as the client (`takeWholeTicks`): real time earns ticks of `FIXED_DT`, catch-up is capped at `MAX_CATCH_UP_SECONDS`, and nothing else calls `step`. A throw from the sim or the room is logged with the seed and the tick, then rethrown: the process dies loudly and whatever supervises it restarts a fresh world.
- Seats are slots 0-4, lowest free first. A join queues `player/join`; the welcome (`world/welcome`) carries the full state taken after the tick that processed it, so the client finds its own entity in it. A leave, consented or dropped, frees the seat and queues `player/leave`. A session that has not acknowledged its join `JOIN_ACK_TIMEOUT_MS` after its welcome is closed (Colyseus would otherwise buffer every update for it without bound); a client must register its update handlers before awaiting the welcome, see ADR 0005.
- Inbound messages pass the inbound gate in `src/world/inbound.ts`: only `player/move` and `world/resync` are handled; every other type is dropped and counted, and a session that keeps sending unknown types past its budget is closed. Each session has a token budget (`INBOUND_BURST`, then `INBOUND_MESSAGES_PER_SECOND`; over it, dropped), a decoded payload longer than `MAX_INBOUND_BYTES` is dropped, and a move must be exactly `{ x, y }` with finite numbers, so a payload that carries a `slot` is dropped. The command that reaches the sim carries the session's slot, never anything from the payload. Frames over `MAX_FRAME_BYTES` are refused by the transport, which closes that connection (code 1009, with one `Max payload size exceeded` stack trace in the log per attempt); a flood past `DISCONNECT_MESSAGES_PER_SECOND` is disconnected by Colyseus. HTTP request bodies are capped by the front's request guard (see above).
- Outbound: every `TICKS_PER_SEND` ticks each welcomed session gets a `world/delta` diffed from the last state sent to it (sessions at the same tick share one diff), or a `world/state` if it asked for one with `world/resync` (many requests collapse into one state, and resyncs have their own small budget: `RESYNC_BURST`, then `RESYNCS_PER_SECOND`).

Tuning lives in `src/world/tuning.ts`; game rules do not live here at all.

## Tests

`pnpm --filter @novaland/server test` runs the unit tests of the gate, the seats, the tick helper, the origin policy, the request guard and the front routes, then `startServer.test.ts`, which starts the real composition on a free port (files, headers, compression, the origin policy on matchmaking and upgrades, the body cap, the requests Colyseus cannot survive, and a real client joining through all of it), plus `worldRoom.test.ts`: a real server on a free port and real `@colyseus/sdk` clients that build replicas from what they receive, covering five joins on distinct avatars and tiles, movement seen by everyone, the refused sixth, a leaver's freed seat and vanished avatar, junk dropped while the world runs, a move flood, an unknown-type flood, a refused frame, a resync and a resync flood, a connection that never acknowledges its join, and the room driven directly through a join that leaves mid-tick and a dispose during a join.
