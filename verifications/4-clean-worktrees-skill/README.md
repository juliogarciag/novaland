# Verification: clean-worktrees skill (ticket #4)

The skill is a procedure an agent follows, so `procedure.mjs` implements it step for step and the verifications drive that implementation. What they prove is that the procedure as written works; an agent that departs from the text is outside their reach. `01-fixture.mjs` therefore also checks that `SKILL.md` states the same commands, patterns, default, age comparison, keep-reason order and prohibitions as the implementation, so the two cannot diverge on those points without a failing check.

- `01-fixture.mjs`: builds a throwaway repository in the system temp dir with thirty worktrees, a fake `gh` that answers from a table and records every call, and a `git` shim that records every call. It checks every branch of the rule (merged, closed, open, two PRs, mixed, no PR, cross-repository PR, merged PR with commits after it, ticket number that is a PR, old and fresh untracked, exact age boundary, fresh worktree on an old base, fresh `.git` file on an old commit, unknown state), every keep reason of step 3 (locked, prunable, detached, unusual slug, unusual branch, outside `.worktrees/`, names differ, nested worktree, default branch, current session, uncommitted changes, running process, `lsof` failure), lookup failures for PR and ticket, argument validation, the preview format and order, the confirmation question, and a real removal where one worktree is dirtied, one locked and one given a running process after the preview and one fails inside git. It asserts the shim never saw `--force` or a branch deletion. Everything lives under the temp dir, which is deleted on exit or signal.
- `02-live.mjs`: the same procedure against this repository with the real `gh`, preview only. Checks that depend on worktrees that may be gone later are reported as `SKIP`.
- `proof/`: output of the last run with every check line, machine-specific paths replaced and pids normalised.

Not covered, because it cannot be scripted: step 7's human answer. The procedure returns the question; it has no code path that proceeds without the caller. `disable-model-invocation` in the frontmatter keeps the model from starting the skill on its own, and `git worktree remove` is not in any allowlist, so the permission prompt remains the last gate. A `bare` entry is parsed but has no fixture, since a linked worktree cannot be bare.

Run `bash verifications/4-clean-worktrees-skill/run.sh` from anywhere. It needs `git` 2.36 or later, `gh` (authenticated, for `02-live`) and `lsof`.
